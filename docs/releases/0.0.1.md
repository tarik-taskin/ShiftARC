# ShiftARC 0.0.1 — Lokal Teknik Temel

Yayın tarihi: 19 Haziran 2026
Durum: Lokal geliştirme kilometre taşı

## Sürüm özeti

`0.0.1`, ShiftARC'ın ilk sürümüdür. Önceki durumda yalnızca yeni oluşturulmuş bir
Vite/React/TypeScript projesi bulunuyordu; bu sürümle repository, lokal ortamda
birlikte çalışan React frontend, Spring Boot API ve PostgreSQL veritabanından
oluşan doğrulanabilir bir uygulama temeline dönüştü.

Bu sürüm son kullanıcıya yönelik planlama özelliklerini sunmaz. Amacı; görevler,
gün tipleri, zaman blokları, trigger'lar ve planlama algoritması geliştirilmeden
önce bu özelliklerin üzerinde güvenle büyüyebileceği teknik sınırları kurmaktır.

## Önceki durumdan farklar

### Repository ve çalışma alanı

- Frontend ve backend bağımsız modüller olarak tek repository altında düzenlendi.
- Ortak API sözleşmesi `contracts/openapi/` altında kaynak doğru olarak ayrıldı.
- Lokal bootstrap, geliştirme ve kalite komutları `scripts/` altında toplandı.
- Build çıktıları, dependency klasörleri, loglar ve lokal secret dosyaları Git
  kapsamı dışında bırakıldı.
- İnsan geliştiriciler ve code agent'lar için mimari, güvenlik, test ve commit
  kuralları `AGENTS.md` içinde kalıcı hale getirildi.

### Veritabanı temeli

- PostgreSQL 16 için `shiftarc` veritabanını ve sınırlı `shiftarc_app` rolünü
  oluşturan idempotent PowerShell bootstrap akışı eklendi.
- Uygulama bağlantısı environment değişkenleriyle yapılandırıldı; gerçek parola
  repository içine alınmadı.
- HikariCP bağlantı havuzu lokal geliştirme için sınırlı ve fail-fast değerlerle
  ayarlandı.
- Flyway migration altyapısı etkinleştirildi. İlk migration uygulamaya ait
  `shiftarc` şemasını oluşturur; otomatik Hibernate DDL üretimi kapalıdır.
- Uygulanmış migration'ların değiştirilmemesi ve her şema değişikliğinin yeni,
  sıralı migration olması proje kuralı haline getirildi.

### Backend

- Java 17 ve Gradle Wrapper kullanan Spring Boot 4.1 API modülü oluşturuldu.
- Build metadata'sından sürüm okuyabilen executable JAR üretimi eklendi.
- `GET /api/v1/system/status` endpoint'i API ve PostgreSQL erişilebilirliğini
  birlikte doğrulayacak şekilde geliştirildi.
- Başarılı durum yanıtında servis adı, uygulama sürümü, API durumu ve veritabanı
  durumu sunulur.
- Veritabanı erişilemediğinde internal JDBC ayrıntısı veya secret sızdırmadan
  standart HTTP 503 Problem Details yanıtı döndürülür.
- Actuator yüzeyi yalnız genel health endpoint'iyle sınırlandı ve ayrıntılı sağlık
  bilgileri kapatıldı.

### API sözleşmesi

- OpenAPI 3.1 sözleşmesi `contracts/openapi/shiftarc-api.yaml` altında eklendi.
- Sistem durumu endpoint'inin 200 ve 503 davranışları ile response şemaları
  tanımlandı.
- Endpoint ve payload değişikliklerinde sözleşme, backend, frontend client ve
  testlerin birlikte güncellenmesi zorunlu kılındı.
- Bu sürümde anonim tek bir teknik durum endpoint'i vardır; authentication veya
  kullanıcı verisi işleyen bir API bulunmaz.

### Frontend

- React 19, TypeScript 6 ve Vite 8 tabanı ShiftARC web modülü olarak düzenlendi.
- `/api` isteklerini lokal Spring Boot servisine yönlendiren Vite proxy eklendi.
- Sistem durumu için response doğrulayan typed API client ve React hook yazıldı.
- Lokal foundation ekranı frontend, API ve PostgreSQL durumlarını ayrı kartlarda
  gösterir; loading, success, error ve retry akışlarını destekler.
- Klavye erişilebilirliği, anlamlı durum metinleri, responsive görünüm ve
  `prefers-reduced-motion` tercihi ilk UI temelinde dikkate alındı.

### Lokal geliştirme deneyimi

- `scripts/dev.ps1`, frontend ve backend süreçlerini tek komutla veya ayrı ayrı
  başlatır; kapanışta alt süreçleri temizler.
- `-CheckOnly` modu Node.js, Java, PostgreSQL, Gradle Wrapper, portlar ve zorunlu
  environment değerlerini servis başlatmadan kontrol eder.
- `.env.local.example`, secret içermeyen lokal yapılandırma sözleşmesini sağlar.
  Terminal environment değerleri lokal dosyadan önceliklidir.
- PostgreSQL bootstrap, ilk kurulum, ayrı servis çalıştırma ve sorun giderme
  adımları root `README.md` içinde belgelendi.

## Veri ve güvenlik etkisi

Bu sürüm kullanıcı hesabı veya kişisel planlama verisi oluşturmaz ve işlemez.
Veritabanındaki tek kalıcı uygulama değişikliği, Flyway geçmişi ile uygulamaya ait
boş `shiftarc` şemasıdır.

Kurulan güvenlik tabanı:

- Uygulama PostgreSQL superuser yerine sınırlı rolle çalışır.
- Veritabanı parolası zorunludur ve source code içinde varsayılan değeri yoktur.
- `.env.local`, loglar ve build çıktıları Git'e alınmaz.
- API hata yanıtları internal exception ve bağlantı ayrıntılarını açığa çıkarmaz.
- Actuator ayrıntıları dışarı sunulmaz.
- Test profili gerçek lokal PostgreSQL'e bağlanmaz ve geliştirici verisini
  değiştirmez.

Bu önlemler production güvenlik çözümünün tamamı değildir. Authentication,
authorization, rate limiting, güvenli cookie/session yönetimi, production secret
manager ve ağ güvenliği ürün özellikleriyle birlikte ayrıca tasarlanacaktır.

## Kalite ve doğrulama

Repository seviyesindeki `scripts/check.ps1` kalite kapısı şu kontrolleri tek
akışta çalıştırır:

1. Frontend ESLint
2. Frontend Vitest ve Testing Library testleri
3. TypeScript kontrolü ve Vite production build
4. Backend JUnit/MockMvc testleri
5. Spring Boot executable JAR build

Sürüm kapanışında frontend testlerinin tamamı (4 test), frontend lint/build ve
backend test/JAR görevleri başarıyla tamamlandı. Backend test kapsamı; servis
davranışı, HTTP sözleşmesi, uygulama context'i, lokal environment fail-fast
kontrolü ve migration kaynak bütünlüğünü içerir.

## Geliştirme süreci

Sürüm aşağıdaki sıralı amaçlarla oluşturuldu:

1. Vite/React/TypeScript tabanının kurulması
2. Monorepo sınırlarının ve repository standartlarının belirlenmesi
3. PostgreSQL bootstrap ve lokal environment sözleşmesinin hazırlanması
4. Spring Boot/Gradle API temelinin oluşturulması
5. Flyway migration politikasının uygulanması
6. Contract-first sistem durumu endpoint'inin geliştirilmesi
7. Typed frontend client ve teknik durum ekranının bağlanması
8. Tek komutlu lokal geliştirme ve kalite akışlarının eklenmesi
9. Testlerin, dokümantasyonun ve agent çalışma kurallarının tamamlanması
10. Sürüm tutarlılığı ve tam kalite kapısının doğrulanması

Bu sıra, domain geliştirmesine başlamadan önce veritabanı sahipliği, API sınırı,
secret yönetimi ve test davranışının görünür olmasını sağladı.

## Bilinen sınırlar

`0.0.1` kapsamında aşağıdakiler bulunmaz:

- Authentication, authorization ve çok kullanıcılı veri izolasyonu
- Görev, kategori, gün tipi, zaman bloğu ve takvim domain modelleri
- İş parçacığı, alışkanlık ve trigger davranışları
- Otomatik süre dağıtımı ve önceliklendirme algoritması
- Dijital saat, günlük zaman çizelgesi ve gerçek ürün navigasyonu
- Pomodoro, tarayıcı bildirimi ve sesli uyarılar
- Production deployment, container veya CI/CD pipeline
- Telemetry, merkezi loglama, backup/restore ve disaster recovery
- Ödeme, abonelik veya herkese açık kullanıcı kaydı

Foundation ekranı geçici bir teknik doğrulama yüzeyidir; nihai ShiftARC ana sayfası
olarak değerlendirilmemelidir.

## Yükseltme ve geri dönüş

Bu ilk sürüm olduğu için önceki bir ShiftARC sürümünden veri migration'ı yoktur.
Lokal kurulum için root `README.md` adımları izlenir. Uygulanmış Flyway migration'ı
elle geri alınmamalı veya düzenlenmemelidir. Lokal foundation'ı kaldırmak gerekirse
uygulama süreçleri durdurulmalı; veritabanı veya rol silme işlemi geliştirici
tarafından bilinçli ve ayrı bir yönetim işlemi olarak yapılmalıdır.

Bir sonraki sürüm domain geliştirmesine geçtiğinde veri modeli, sahiplik sınırları,
authentication kararı ve planlama algoritmasının deterministik test stratejisi
tasarımın parçası olmalıdır.
